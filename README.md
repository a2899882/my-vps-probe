# My VPS Probe

轻量、自托管的 VPS 状态探针。单个 Go 主控 + 单个 Go 被控端，提供实时资源监控、TCP 延迟历史、月流量配额、到期管理、分组、Telegram 通知与迁移备份。

## 功能

- 明暗双主题监控页，支持卡片/精简表格视图、搜索、分组、状态筛选、排序和分页
- CPU、内存、Swap、磁盘、负载、上下行速率/流量、TCP/UDP 连接数与系统在线时长
- 资源历史和 TCP Ping 历史图表，Ping 目标可单独分配到指定节点
- 节点到期日、月流量上限和自定义重置日
- Telegram 离线、恢复和到期通知，事件自动去重
- 后台批量分组、批量删除、置顶/置底、移动到指定位置、永久应用排序、JSON 导入导出
- 后台可调历史保留天数、前台刷新间隔和 Agent 上报间隔
- `tz` 命令更新、状态、域名反代、防火墙、备份、恢复和卸载
- SQLite WAL、定时清理、延迟缓存与月流量定时原子落盘，适合低配 VPS

## 一键安装主控

支持 Debian/Ubuntu、systemd、amd64/arm64：

```bash
curl -fsSL https://raw.githubusercontent.com/a2899882/my-vps-probe/main/install-master.sh | bash
```

安装完成后访问 `http://服务器IP:8080`，后台地址为 `/admin`。首次默认账号为 `admin`、密码为 `123456`，请立即在“系统设置”中修改。

需要域名与自动 HTTPS 时，在 VPS 执行：

```bash
tz
```

选择“添加域名访问”，脚本会配置 Caddy 反向代理。

## 添加被控端

在后台“节点管理”中新建节点，点击该节点的“部署”图标复制命令，再到目标 VPS 执行。Agent 使用 systemd 常驻并自动重连，Token 存放在权限为 `0600` 的 `/etc/probe/agent.env`，不会显示在进程参数中。

## 更新

主控 VPS 执行 `tz`，选择 `1. 更新探针主控端`。更新过程会：

1. 拉取最新源码；
2. 在临时目录编译主控与 amd64/arm64 Agent；
3. 编译成功后原子替换文件并重启；
4. 通过 `/healthz` 健康检查确认服务可用。

新版 Agent 功能需要在对应节点重新执行一次后台生成的部署命令；旧 Agent 可继续连接。

> 从旧版首次升级到当前“纯源码轻量仓库”时，请先重新执行一次上面的主控一键安装命令。新版安装器会处理旧版已跟踪的二进制文件、保留 `config.json` 和数据库、安装新版 `tz` 菜单；以后继续使用 `tz` 更新即可。

## TCP Ping 时间格与资源告警

每格对应一个实际接收数据的 UTC 分钟，显示该分钟的平均延迟，浏览器按当地时间显示。探测结果先在内存中按分钟汇总，再批量落库；数据库临时写入失败时最多保留近 60 分钟待写样本并重试，正常重启前会刷新当前分钟。卡片右侧显示近 60 分钟成功样本的平均延迟，最新实时值保留在悬停说明中。

- 绿色：有成功样本且平均延迟低于 150ms；黄色：平均延迟达到 150ms 或本分钟有部分失败；红色：本分钟样本全部失败；灰色：该分钟未采集。
- 灰色：该分钟没有收到数据，例如离线、重启期间或尚未开始监测。悬停可查看具体时间和说明。
- 旧版本已丢失的历史样本无法重建，会在 60 分钟窗口内逐渐移出。升级后无需重新安装 Agent 即可修复新数据的时间格。

后台“通知”中提供独立开关：离线、到期、恢复、CPU、内存、硬盘、月流量。新增资源告警默认关闭；旧 Telegram 凭据和原有通知设置保留。

| 告警 | 默认阈值（启用后） | 连续超限时间 |
| --- | --- | --- |
| CPU | 使用率 90% | 180 秒 |
| 内存 | 使用率 90% | 60 秒 |
| 硬盘 | 根分区使用率 90% | 300 秒 |
| 月流量 | 节点月配额 80% | 立即 |

阈值和持续时间均可调整。只有连续收到有效上报才累计超限时间；低于阈值会重计持续时间，超过上报宽限期的断线也会重计。恢复线为告警阈值减 5 个百分点，默认持续 60 秒后解除，可关闭恢复消息。未设置月流量配额的节点不触发流量告警，配额按上传与下载合计及节点重置日计算。

“重复提醒”设为 0 时，每次告警仅首次通知；设为分钟数可在告警持续期间定期提醒。支持排除指定节点的全部通知。通知按小批次合并，正常情况下每 5 秒最多发送一条合并消息，失败或 Telegram 限流后延迟重试；发送成功才保存去重状态。重启时不会把未上报的节点误判为恢复上线。

最近推送记录仅管理员可见，包含成功和失败原因，最多 1000 条并定期清理 7 天前记录。测试消息也会记入记录，但失败的手动测试需重新点击发送。生产运行无需 Node.js；`tests/frontend` 只用于开发及 CI 校验。

## 卡片和趋势性能

卡片每个 Ping 目标使用一条 CSS 色带绘制 60 个分钟格，悬停或使用左右方向键时才生成该分钟的时间提示。卡片更新与时钟、主题、详情面板隔离，历史数组使用浅响应式；大量节点分页保留已有卡片，屏幕外卡片延迟绘制。明暗主题保留，去掉了卡片和详情背景的大面积模糊滤镜。

趋势面板复用图表实例，快速切换节点或时间范围会取消旧请求并忽略过时结果；最近 12 组非空范围数据缓存 60 秒，空结果会自动重试。图表库与历史并行加载，资源图分帧更新，加载失败可直接重试。实时选项表示最近 15 分钟；刚上线尚未写入首个分钟历史时会显示当前实时采样点。长范围在查询时按时间桶汇总，每条曲线最多约 480 个点；资源图显示桶内峰值，延迟图显示均值及分钟失败率均值，界面会标注分辨率。未采集区间保持断点，延迟图可显示红色断流、黄色部分失败和灰色未采集标记，原始分钟历史继续按保留天数存储。

## 本月流量校准

后台“节点”列表现在显示 **本月已用 / 配额**，点击用量即可校准；勾选多台后，可使用“流量校准”批量操作。

1. 保存当前节点配置，再打开流量校准窗口。
2. 选择“归零”，或填写当前账期上传＋下载合计的已用 GB。可输入 6 位小数，单位沿用原配额口径：1 GB = 1024³ 字节。
3. 核对每台节点的账期、旧值和新值，点击“校准并立即保存”。多台时，每台设为相同数值，不会平分。

校准直接原子保存到 `usage_state.json`，不依赖页面顶部的配置保存。窗口保留最近一次校准的时间、账期、前后数值；同时校准同一节点的旧窗口会提示冲突。批量操作先检查全部节点，任意校验或写入失败均不应用这批修改。资源、Ping 历史和系统网卡计数不被清除。

在线节点以最新有效上报为基线继续累计。离线或从未上报的节点会保留填写值，在下次有效上报时建立基线，避免把接入前的全部计数加进来；这个间隔中的流量无法精确还原，不会补算。新账期按节点配置的 1–28 日开始，即使节点离线，前台也会显示新账期用量；首次上报重新建立该周期的基线。修改重置日导致账期改变时也会重新建立基线，请随后按需要校准。

系统累计与本月用量口径不同：系统累计来自网卡原始计数，可能因重启或网卡变化而下降；本月用量由主控持久记录上报增量。旧状态文件自动兼容，上传和下载分别计算增量。新版 Agent 额外上报开机标识、采集有效性和各网卡计数，改善重启、网卡新增/移除以及采集失败时的统计与速率；**这些采集增强需要在被控端重新执行后台生成的部署命令**。仅更新主控即可使用页面提速、趋势优化和流量校准，旧 Agent 继续兼容。

默认保留原有的全部网卡统计范围，因此回环、容器和隧道可能与服务商账单口径不同，服务商也可能只计一个方向或使用十进制 GB。请按同一口径核对再校准；缺失的历史数据无法精确重建。流量配额告警会跟随校准后的用量，在新的有效上报后判断超限及恢复。

## 备份与恢复

执行 `tz`：

- 选择 `9` 生成包含 `config.json`、`data.db`、月流量状态及校验文件的压缩包；
- 将备份上传到新 VPS，再选择 `10`，输入完整路径恢复；
- 恢复前会自动额外创建一份保护备份。

## 规模建议

默认设置适合几十台节点。达到 100 台以上时，建议把前台刷新和 Agent 上报间隔调整为 5 秒；历史数据通常保留 7–30 天即可。1 核 512MB–1GB 内存足以承载常规团队使用，数据库空间主要由“在线节点数 × Ping 目标数 × 保留天数”决定，系统会按设置每小时清理过期记录。

## 开发

```bash
go test ./...
go build -o probe-server ./server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o server/probe-agent-amd64 ./agent
npm ci --prefix tests/frontend --ignore-scripts
npm test --prefix tests/frontend
node tests/integration/smoke.cjs ./probe-server
```

运行目录需要包含 `server/index.html`、`server/admin.html` 和 `install.sh`。运行状态文件会自动生成，均已加入 `.gitignore`。

## 目录

- `server/`：主控、Web UI、历史和通知
- `agent/`：被控端采集与并行 TCP 探测
- `common/`：主控与 Agent 共用协议
- `scripts/tz.sh`：主控管理菜单
- `install-master.sh`：主控一键安装
- `install.sh`：被控端一键安装
